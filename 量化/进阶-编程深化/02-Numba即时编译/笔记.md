# 进阶·编程深化 ② Numba 即时编译（JIT）

> [① C++ 课](../01-CPP加速蒙特卡洛/笔记.md) 的结论:路径依赖+提前退出的问题,C++ 比 NumPy 快——但写 C++ 要另起一套(头文件/编译/绑定)。
> **Numba 给出第三条路:给普通 Python 循环加一行 `@njit`,它就被即时编译成机器码,速度逼近 C++,而你一行 C++ 都没写。**
> 对"Python + 一点 C++"的你,这常常意味着:**根本不用上 C++**。配套代码:[`numba_jit.py`](numba_jit.py)。

> 🧭 本质 → 一行装饰器 → 实测(≈C++,零C++) → 何时用谁 → 闭环。

---

## 一、本质（一句话）

> **Numba 把"慢的 Python 循环"在运行时编译成机器码。** 你保留 Python 的写法(可读、可改),却拿到接近 C++ 的速度——只需一行 `@njit` 装饰器。

---

## 二、就一行装饰器

对比 [① 的 C++](../01-CPP加速蒙特卡洛/笔记.md):C++ 要写 `.cpp`、配 pybind11、编译成 `.so`。Numba 只要:

```python
from numba import njit

@njit                      # ← 就这一行
def barrier_numba(S0, K, B, r, sigma, T, n, steps):
    ...                    # 普通的 Python 双重循环,带 if/break(提前退出)
    return price
```

第一次调用时 Numba 把它**即时编译(JIT)** 成机器码(有一次性编译耗时,之后飞快)。**代码几乎和纯 Python 一模一样**,但快几十倍。

---

## 三、实测:Numba ≈ C++,却零 C++ ⭐

同样的两个问题(对照 [①](../01-CPP加速蒙特卡洛/笔记.md)):

**欧式期权(可向量化)**——实验②:

| 方法 | 耗时(n=30万) |
|---|---|
| 纯 Python | 247 ms |
| NumPy | 7.3 ms |
| **Numba** | 12.5 ms |

Numba ≈ NumPy(同档),都比纯 Python 快 ~20×。**可向量化的问题,NumPy/Numba 都行。**

**障碍期权(路径依赖 + 提前退出)**——实验③:

| 方法 | 耗时(n=8万,steps=250) |
|---|---|
| 纯 Python | 3087 ms |
| NumPy(不能提前退出) | 327 ms |
| **Numba(能提前退出)** | **177 ms** |

> **关键对照**:[① 的 C++](../01-CPP加速蒙特卡洛/笔记.md) 在**同样**的障碍问题上是 **161 ms**;Numba 是 **177 ms**——**几乎一样快!** 也就是说:这个让 C++ 大显身手的路径依赖问题,**Numba 用一行装饰器就追平了 C++,你完全不用写 C++**。它比 NumPy 快 1.8×(因为能对单条路径 `break`)。

---

## 四、何时用谁?(更新版决策树)

把 [① 的决策清单](../01-CPP加速蒙特卡洛/笔记.md) 升级:

1. **能向量化?** → 用 **NumPy**(最简洁,够快)。
2. **难向量化(逐路径、提前退出、复杂分支)?** → 先试 **Numba**(`@njit`,零成本逼近 C++)。
3. **Numba 还不够 / 要接现成 C++ 库 / 极致低延迟?** → 才上 **C++ + pybind11**([①](../01-CPP加速蒙特卡洛/笔记.md))。

> 对绝大多数量化研究,**第 2 步(Numba)就是终点**。C++ 留给真正的生产级/低延迟系统。

**Numba 的注意点**:
- **首次调用有 JIT 编译耗时**(计时要先"预热"一次,代码里 `euro_numba(...,10)` 就是预热)。
- **只支持 Python/NumPy 的一个子集**(`@njit` 的 "nopython" 模式):纯数值循环最爽;pandas、复杂对象不行。
- `cache=True` 可把编译结果存盘,下次免编译。

## 五、思维模型

1. **抽象不必牺牲速度**:Numba 让你**用高层语言写、拿低层速度**——"可读"和"快"不再是单选题。
2. **JIT = 运行时才编译**:它在第一次调用时"看到"实际类型,生成专门的机器码。**延迟编译,换取灵活 + 速度**。
3. **阶梯式优化**:NumPy → Numba → C++,每级更快也更费劲。**爬到够用那级就停**(呼应 [① 别过早优化](../01-CPP加速蒙特卡洛/笔记.md))。
4. **工具的性价比**:一行装饰器换 17× 加速,是性价比极高的优化。**先摘最低的果子。**

---

## 六、哲学指导

> **Numba 体现了"用对工具,鱼与熊掌可兼得"。** [① 让你看到 C++ 的威力与代价](../01-CPP加速蒙特卡洛/笔记.md),这一课让你看到:很多时候那个代价**根本不用付**——一行 `@njit` 就拿到了八九成的好处。

这对自学者尤其重要:**别被"高性能=必须写 C++"吓退**。先用 Numba,等真撞到它的天花板(罕见),再考虑 C++。**把精力留给真正重要的事(找信号、控风险),而不是和编译器搏斗。** 这也是一种"诚实地评估成本收益"——和全项目反对"为复杂而复杂"一脉相承。

## 七、动手

跑 `python numba_jit.py`,然后:

1. **删掉预热**:把 `euro_numba(...,10)` 那两行预热删掉,看首次计时被 JIT 编译耗时污染——理解"为什么要预热"。
2. **对照 C++**:把这里障碍期权的 Numba 耗时,和 [① 的 C++ 耗时](../01-CPP加速蒙特卡洛/笔记.md)比——是不是几乎一样?
3. **njit 你自己的循环**:挑一个你写过的慢 Python 循环(比如事件驱动回测),加 `@njit` 看能不能跑通、快多少(注意:用不了 pandas)。
4. **parallel=True**:给 `@njit(parallel=True)` 配合 `numba.prange` 做多核并行,看障碍期权再快几倍。

## 八、本课小结（费曼版）

- **Numba = `@njit` 一行,把 Python 循环即时编译成机器码**,速度逼近 C++,代码几乎不变。
- **实测**:障碍期权(路径依赖)Numba **177ms ≈ [① 的 C++ 161ms](../01-CPP加速蒙特卡洛/笔记.md)**,比 NumPy 快 1.8×、比纯 Python 快 17×——**追平 C++,零 C++**。欧式(可向量化)Numba ≈ NumPy。
- **决策树**:能向量化→NumPy;难向量化→先试 Numba;Numba 不够/要低延迟→才上 C++。
- **注意**:首次 JIT 编译耗时(要预热);只支持 Python/NumPy 子集(没 pandas)。
- **心法**:抽象不必牺牲速度;摘最低的果子;别被"高性能=写C++"吓退。
