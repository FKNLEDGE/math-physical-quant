# 学习计划 · 把 60+ 模块变成"你真的会" 📅

> 内容已经很全,**但"读完"不等于"学会"**。这份计划把全项目编成一条**按周推进、边读边跑边练**的路径,
> 让你不迷路、不焦虑、不烂尾。配三种节奏,你按自己的时间挑。
>
> 📌 **最重要的一句**:**少读多做。** 每个模块都**先读笔记 → 再跑/改代码 → 最后用人话复述 + 做一道[练习题](13-练习册.md)**。
> 看不懂就回到"最简单的例子"和"动手代码",别硬啃公式。

## 二、如何学每个模块（雷打不动的三步）

1. **读**笔记.md——重点看"本质一句话 + 最简例子 + 费曼小结",公式看不懂先跳过。
2. **跑**配套 .py——先原样跑出那张四合一配图,再**改一个参数**重跑,看结果怎么变(动手才有手感)。
3. **复述 + 练**——合上笔记,用大白话给"想象中的朋友"讲一遍这模块在干嘛;再做 [练习册](13-练习册.md) 里对应的 1 道题。

> ✅ **过关标准**:能不看笔记、用大白话讲清楚 = 学会了。讲不清 = 回去再读"最简例子"。

## 五、不烂尾的几条军规

1. **先广后深**:别一上来钻进某个公式出不来。**先把主干走通,细节回头补。** 看不懂就跳过,做下去常常自然就懂了。
2. **动手 > 阅读**:每周至少**亲手改一次代码、跑出一张图**。被动读笔记,一周后忘光;改过的代码,记一辈子。
3. **每周一个小成果**:跑出一张图、讲清一个概念、做对一道题——**可见的小胜利**是坚持的燃料。
4. **允许"不完美理解"**:数学物理的东西,**先会用、后理解、再批判**。第一遍懂 60% 就往前走。
5. **用 git 记录成长**:每学完一块 commit 一次,[06 大纲](06-深入学习大纲.md)打个勾。**回头看 git 历史,就是你的进步轨迹。**
6. **卡住了**:回 [08 术语表](08-量化术语表.md) 查词、回 [10 思考题答案](10-思考题参考答案.md) 对思路、或直接问我。**卡住是正常的,不是你笨。**
